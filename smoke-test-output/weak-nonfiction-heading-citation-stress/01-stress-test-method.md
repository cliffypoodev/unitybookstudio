# Weak Nonfiction Heading/Citation Stress Test — Methodology

**Pipeline:** recast v4
**Date:** 2026-06-09
**Status:** PASS WITH NOTES

---

## Why This Test Exists

The v4 bakeoff validated recast behavior on thriller and literary fiction samples, producing measurable score improvements (+2 and +4 respectively). However, nonfiction was not exercised under pressure. The bakeoff verdict was **PASS WITH NOTES** in part because nonfiction recast remained untested against a deliberately weak sample containing structural elements (headings, citations) that the pipeline must preserve.

This stress test closes that gap. It constructs a worst-case nonfiction input—loaded with detectable weaknesses but also carrying structural elements that must not be damaged—and runs it through two pipeline configurations to exercise both the default safety gates and the forced-recast path.

---

## How the Weak Sample Was Crafted

The sample is a **652-word trade nonfiction article about municipal water infrastructure**. It was hand-crafted, not generated by an LLM. Every weakness was placed deliberately to trigger specific pipeline detectors:

| Element | Count | Purpose |
|---|---|---|
| Filter verbs | 18 (27.6/1K density) | Trigger `filter_verb_heavy` weakness detection |
| Essay-bot transitions | 10 | Trigger `essay_bot_transitions` weakness detection |
| Chatbot patterns (total) | 22 | Inflate detectable weakness count |
| Vague abstraction-heavy paragraphs | Multiple | Simulate low-quality prose that should score poorly |
| Markdown headings (`##`) | 4 | Exercise heading preservation gate |
| Citation-like parentheticals | 3 | Exercise citation protection gate |
| Bulleted list | 1 | Exercise structural preservation |

### Filter Verbs Used

`felt`, `realized`, `noticed`, `watched`, `seemed`, `wondered` — distributed across the text at 27.6 per 1,000 words.

### Essay-Bot Transitions Used

`Moreover`, `Furthermore`, `Additionally`, `It is important to note` — the classic markers of formulaic writing.

### Citations Embedded

| Citation | Format |
|---|---|
| (ASCE, 2021) | Standard org-year |
| (Hanna-Attisha et al., 2016) | Hyphenated surname with et al. |
| (Kearney & Liu, 2023) | Multi-author with ampersand |

### Composite Score

**76 GOOD** — above the default recast threshold (70) but below the skip threshold (80). This positions the sample in the zone where pipeline behavior depends on chunk-level scoring and structural protections.

## Two-Run Methodology

The test uses two runs against the same sample to exercise different layers of the pipeline's safety infrastructure.

### Run 1 — Default Protections

| Parameter | Value |
|---|---|
| Threshold | 70 |
| Skip | 80 |
| Purpose | Verify default safety gates block recast correctly |

**Expected behavior:** Chunks containing citations should be blocked by citation protection. Chunks scoring above the threshold should be skipped. No recast should occur.

### Run 2 — Forced Recast

| Parameter | Value |
|---|---|
| Threshold | 80 |
| Skip | 95 |
| Purpose | Force the pipeline to attempt recast; exercise downstream safety gates |

**Expected behavior:** Citation protection should still block citation-bearing chunks. Remaining chunks should be sent to the model. If the model produces damaged output (compression, heading loss, etc.), downstream safety gates should catch it and preserve the original.

---

## Why Forced Recast Matters

Default protections are the first line of defense, but they are not the only line. Forced recast exercises the pipeline's behavior when a chunk *does* reach the model:

1. **Routing:** Does the pipeline select the correct model and temperature for nonfiction?
2. **Weakness detection:** Does the pipeline correctly identify the input's weaknesses?
3. **Quality guard:** If the model produces bad output, does the word-count compression gate catch it?
4. **Heading preservation:** If the model drops headings, does the heading gate catch it?
5. **Citation preservation:** Are citation preservation instructions included in the recast prompt?

A pipeline that only works because nothing reaches the model is untested. A pipeline that catches model failures and preserves the original is proven.
