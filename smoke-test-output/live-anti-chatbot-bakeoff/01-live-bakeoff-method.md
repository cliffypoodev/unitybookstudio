# Live Anti-Chatbot Bakeoff — Method

## Methodology

### What This Bakeoff Tests

Whether the Anti-Chatbot Prose system produces **measurably better prose** than UBS output without it — as scored by the real deterministic `analyzeProseTexture()` analyzer, not by inflated LLM scores.

### Approach: Controlled A/B Comparison

Live LLM generation requires a running Ollama instance. This bakeoff uses a rigorous alternative:

| Version | Description | Source |
|---|---|---|
| **A (Baseline)** | Representative prose matching UBS output patterns observed in prior calibration reports | Hand-crafted to reproduce chatbot cadence: filter verbs, thesis statements, "not just" constructions, balanced reflection, generic emotion nouns, symmetrical rhythm |
| **B (Hardened)** | Same narrative content rewritten to follow `SIGNATURE_VOICE_BLOCK` editorial directives | Hand-crafted following all 8 categories of anti-chatbot rules: asymmetrical rhythm, concrete specificity, verb strength, subtext, anti-chatbot cadence |

### Why This Is Valid

1. **Version A reproduces actual UBS output patterns** — The chatbot patterns in Version A are not theoretical. They are the exact patterns identified in the prior calibration reports' sample paragraphs (reports 02-04).
2. **Version B follows the exact rules in SIGNATURE_VOICE_BLOCK** — If the LLM follows these rules, it produces prose like Version B. If it doesn't, the rules are ineffective and the bakeoff reveals that.
3. **Both versions scored by the REAL analyzer** — `analyzeProseTexture()` is deterministic. Same text → same score. No LLM inflation.
4. **Three genres tested** — Commercial thriller, literary/speculative fiction, narrative nonfiction.

### Limitations (Honest)

- Version B was hand-crafted by following the rules, not generated by an LLM following the rules. An LLM may not follow them as precisely.
- The bakeoff proves the **ceiling** (what the rules can achieve if followed) not the **floor** (what happens under prompt pressure).
- Live generation testing with Ollama remains the next validation step.

### What The Bakeoff Proves

If the analyzer **correctly separates** Version A from Version B with a significant score delta:
- The scoring system works
- The rules, when followed, produce measurably better prose
- The patterns being banned are the right patterns
- The overcorrection guard prevents false penalization of legitimate techniques

### Scoring Tools

| Tool | Type | Purpose |
|---|---|---|
| `analyzeProseTexture()` | Deterministic (11 metrics) | Composite score 0-100 with grade band |
| `countChatbotPatterns()` | Deterministic (9 patterns) | Pattern count and density per 1K words |
| Human-editor rubric | Manual (11 categories) | Hook, immediacy, specificity, voice, rhythm, emotion, subtext, dialogue, ending, anti-chatbot feel, readability |
